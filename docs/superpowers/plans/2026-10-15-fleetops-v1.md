# FleetOps v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. The main agent does most work natively. Consider a subagent only for a clearly independent task with a concrete benefit, and obtain the user's explicit approval first.

**Goal:** Deliver a Docker-run vehicle booking application with two sequential approvals, actual-usage dashboard, and periodic Excel export.

**Architecture:** One Laravel 12 application serves a Vue 3/Vite interface and session-authenticated JSON routes from `routes/web.php`. Docker Compose starts the application and PostgreSQL; the application image contains built frontend assets. Booking rules live in one workflow action with a shared availability query; tests run against a separate PostgreSQL database.

**Tech Stack:** Laravel 12, PHP 8.2+ in Docker, Vue 3, Vite, selected Hope UI layout/assets, PostgreSQL, Docker Compose, PHPUnit; add PhpSpreadsheet only when implementing real `.xlsx` output.

**Spec:** `docs/technical-design.md`. Also read `agent.md` before implementation. The user approved the spec and authorized implementation. The main agent performs the work natively; subagents remain optional and need separate approval.

## Global Constraints

- Target submission: 16 Oktober 2026 pukul 12.00. The first version includes exactly the core delivery in the spec; master-data CRUD, BBM, service, notifications, extra charts, and configurable approvals are not acceptance criteria.
- Business timezone is `Asia/Jakarta`; DB columns use `timestamptz`; HTML `datetime-local` inputs are interpreted as WIB; API timestamps include `+07:00`.
- `approved` is not `used`: usage counts only `completed` bookings by `completed_at` WIB. Periodic reports filter `created_at` WIB with an inclusive start and exclusive next-day end.
- Vehicle and driver conflicts use `[start_at, end_at)` for `pending`, `approved`, `completed`. Early completion does not release the remainder of the reservation slot.
- Exactly two distinct approvers; edit only while L1 is pending; L2 acts after L1 approves. All six successful workflow events produce append-only logs in the same transaction.
- Same-origin Laravel session + CSRF; JSON routes are under `/api/*` in `routes/web.php`. No Sanctum/JWT, Redis, queue service, repository layer, or unrelated dependencies.
- Reviewer deployment uses Docker Compose with `app` and `db`. Use `SESSION_DRIVER=file`, `CACHE_STORE=file`, `QUEUE_CONNECTION=sync`. A test-only Compose service uses a separate PostgreSQL database; never point `RefreshDatabase` at the demo database.
- Pin Docker build images to `php:8.2.34-cli-bookworm`, `node:22.23.3-alpine`, and `postgres:18.6-alpine` (record **actual running** PHP/PostgreSQL/Node/framework versions in README). Never commit real `.env` secrets. Keep `.git`, `docs/`, `agent.md`, and the existing README when scaffolding Laravel into this nonempty repository.
- The `test` service reuses the `app` image. After **every source change before a red/green test command**, run `docker compose build app`, then run that task's `docker compose --profile test run --rm test php artisan test --filter=...`. The database must be ready first. After UI changes, `docker compose up -d --build app` recreates the running app with the new image.
- The user authorized product coding in the current checkout. Do not commit, create branches, or dispatch subagents without separate explicit approval. Subagents remain optional and require a concrete benefit; each task below ends with verification rather than a commit step.

## Review Focus

1. A user outside WIB fills `datetime-local`: Task 4 must persist the same clock time in WIB, and Task 11 must submit its raw string without a browser-timezone conversion.
2. An approver retries a decision or spoofs `level`/`approver_id`: Task 6 must reject unauthorized or replayed actions without duplicate logs.
3. A report crosses midnight or receives `from > to`: Task 9 must apply WIB half-open bounds or return `422`.
4. A client reuses a session after logout or omits CSRF: Task 3 must deny it (`401` or `419`, respectively).
5. An admin edits after L1 decides, or an early-completed booking receives an overlapping new booking: Tasks 5 and 7 must reject these transitions.

The Docker image should use a Node build stage for Vite assets and a PHP CLI stage for Laravel's single demo server. Keep the default Compose launch to two services (`app` and `db`); the `test` service exists only under a Compose profile. For PostgreSQL 18, mount the named data volume at `/var/lib/postgresql` and initialize `fleetops_test` in addition to the demo database on a **fresh** volume. The test service explicitly sets `DB_DATABASE=fleetops_test`; align `phpunit.xml` and `.env.testing` behavior so no SQLite or demo-database override wins. Never add migration/seeding to the container's normal startup command.
